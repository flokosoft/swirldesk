# SwirlDesk MATRIX 0.1.0 — Hyprland TEST

## Installation
Extract overlay in `~/.config/swirldesk` (not into a new nested swirldesk folder). No sudo, no bundled fonts, no changes to FIELD or Debian or Plasma. In Hyprland, use Super+Shift+T and select `swirldesk-matrix`. Existing keyboard bindings, monitor profiles and application rules remain untouched. Reopen Kitty and GTK apps to see all colors. Optional: `bash matrix-support/enable-wallpaper-restore.sh` before switching; it backs up and patches only the exact theme-switcher from the supplied archive. Without it, existing SwirlDesk behavior may leave the MATRIX wallpaper when returning to Debian; choose your previous wallpaper using Super+W. `bash matrix-support/disable-wallpaper-restore.sh` restores the unmodified switcher if the optional patch was installed. Switch back to your old theme before deleting MATRIX files.

## Project state / handoff
Baseline: supplied swirldesk.zip; FIELD Hyprland 1.2.1 changelog, FIELD Plasma 0.9.3.7. Archive includes Graphite as well as Debian and FIELD; Graphite lacks cursor.conf in this snapshot and is not modified. The archive has state/current_theme as an ordinary directory (ZIP may have dereferenced a symlink); the live system should retain its existing theme symlink. Do not copy archived state or Git history over the live system. Theme assumes existing JetBrainsMono Nerd Font, fallback fonts remain available; no fonts supplied.

Design: restrained green-on-black Operator edition. Original procedural static code-rain background, dynamic dwindle, 6/10 px inner/outer gaps, 2 px corners and borders, no blur for laptop efficiency, compact Waybar with actual CPU/MEM/network/audio/battery/notification data. All 10 existing keyboard workspaces remain available, including Signal on 9 and Windows VM on 10. Fuzzel, Kitty, Starship, Dunst, GTK3/4, Hyprlock use independent configs. Existing generic menus and helper scripts can still contain FIELD terminology; no separate Matrix control center yet. No forced monochrome third-party tray pixmaps in Waybar; the Plasma 0.9.3.7 override is unrelated and deliberately untouched. Qt apps, SDDM/greetd, Matrix Plasma variant, animated wallpaper and alternate wallpaper profiles are later work. No global session or security changes. The wallpaper uses no movie image and requires no runtime drawing.

# 0.3.0 — Visual Profiles (TEST)

User confirmed v0.2.0 visually successful on 2026-11-28. Install this incremental overlay over the existing v0.1.0 + v0.2.0 installation. Extract in `~/.config/swirldesk`, then run `bash matrix-support/enable-profiles.sh`, and reselect MATRIX via Super+Shift+T. The guarded installer accepts either the exact original switcher from swirldesk.zip or the v0.1 wallpaper-restore switcher. It preserves the pre-v0.3 version in `matrix-support/backups/theme-switcher.sh.pre-profiles` and refuses unknown custom versions. `bash matrix-support/disable-profiles.sh` restores that exact version if the installed template is unmodified. This only reverts the automatic switcher integration; manual profiles remain. Do not rerun the old enable-wallpaper-restore.sh over the v0.3 switcher. The existing operator dispatcher is unchanged.

Profiles: CLEAN (near-black, subtle green corner marks), CODE RAIN (unchanged original v0.1 wallpaper, default), CONSTRUCT (off-white empty-space inspired background, very faint perspective floor). All three static 2560×1600; no animation, external images, additional service or fonts. Only the wallpaper changes; dark green applications, Waybar, lockscreen and workspace behavior remain the same for readability and consistency. The new Waybar `VIS` module opens a Fuzzel selector, and the Operator Control Center VISUAL / Profile button (also its fallback) opens the same selector. Existing global wallpaper menu still works; Waybar shows CUSTOM if its current-wallpaper cache differs from the saved profile. The profile preference is in `state/matrix_visual_profile`, never shipped in the archive. `visual/profile.sh --current`, `--status`, `--apply clean|code-rain|construct`, `--restore` are available. The selector refuses to change wallpapers when MATRIX is not active, when no Wayland display is set, or when the image/backend is missing. It follows existing SwirlDesk single-swaybg conventions for all outputs, uses a lock for simultaneous profile calls, checks early process survival and updates the existing startup wallpaper cache plus preference after that check. This does not verify compositor rendering; existing generic wallpaper commands are not serialized with it. Fuzzel cancellation leaves state unchanged. On re-entry to MATRIX the installed switcher reapplies the saved profile; on exit to a theme without its own wallpaper the v0.1 previous-wallpaper backup is restored if available. If MATRIX was already activated without a previous wallpaper backup, the old image cannot be reconstructed; select it manually after switching out once. With the optional switcher integration declined, manual selection and login cache still work, but reselecting MATRIX may reset its wallpaper to the default. No changes to other themes, common Hyprland rules/keybinds, Plasma, or the telemetry sampler. Existing lockscreen remains the dark original for all three profiles, deliberately.

Validation: eight unit-test groups passed including prior four telemetry tests, profile switching/cancellation/invalid argument/backend early failure/inactive guard, guarded installer idempotence/rollback/customized-file guard and a mocked Debian → MATRIX → CONSTRUCT → Debian → MATRIX round trip. # 0.4.0 — MATRIX Icon System (TEST)

Incremental overlay over 0.3.1. Extract into `~/.config/swirldesk`, run `bash matrix-support/enable-icons.sh`, then reselect MATRIX through Super+Shift+T. No fonts, root privileges, new services or package upgrades. The local icon theme SwirlDesk-MATRIX uses muted green original SVG line glyphs, with Papirus-Dark/Papirus/Adwaita/hicolor fallbacks for uncovered icons. Fuzzel now shows icons. GTK settings follow the existing theme-switcher links; the guarded switcher adds GSettings icon-theme synchronization only when entering/leaving MATRIX, restoring the selected theme's declared icon theme (FIELD or Papirus-Dark). Existing open applications may need reopening. Qt, Flatpak and applications with absolute icon paths or custom icons may ignore the icon theme. No Plasma modifications. The switcher installer accepts the exact v0.3 profile switcher only (or already-installed v0.4); refuses a custom switcher or a pre-existing nonowned icon directory. Backup kept in matrix-support/backups/theme-switcher.sh.pre-icons. If it refuses, do not force-overwrite the switcher; share its error.

Tray limitation: Debian 13 Waybar 0.12.0 has no documented direct tray icons mapping and draws app-owned pixmaps. The new JSON map is best-effort for newer releases with tray.icons support; no generic Electron ID is overridden to avoid replacing unrelated icons. Even some newer versions can lose overrides on icon updates. Standard named icon lookup may benefit from the theme, but Signal/Bitwarden/Nextcloud tray monochrome is NOT guaranteed. No package upgrade, binary patch or fake tray; original click/menu behavior preserved. Doctor prints installed Waybar version, SNI Id/IconName/Status only, no tooltip content, no pixmap bytes; diagnostic is local/read-only. See Debian trixie waybar-tray(5), unstable waybar-tray(5), upstream 0.12.0 and 0.15.0 src/modules/sni/item.cpp. If colored tray icons remain, the doctor output is the next diagnostic basis.

Rollback: switch to FIELD/Debian/Graphite first, then `bash matrix-support/disable-icons.sh`. It checks the switcher and its backup, plus shipped config hashes, before restoring v0.3.1 config files; assets remain inert. Do not run older enable-profiles/disable-profiles scripts while the new icon switcher is installed. No modifications to wallpapers, existing shared keybinds, control center, other theme files, or Plasma. This release's live test is pending. Next planned: v0.5 Session & Authentication, with dedicated tray work as needed.

Validation: 12 automated test methods passed (8 existing telemetry/visual and 4 icon tests), including mocked MATRIX→FIELD→MATRIX→Debian switching, no icon GSettings writes on unrelated transitions, guarded install/idempotence/rollback and unknown switcher/directory refusal. All 118 SVG files rendered using CairoSVG, XML/manifest/config checks passed, shell syntax checked. Actual GTK/Fuzzel/Waybar rendering, running GSettings and app-specific tray identities remain unverified on the ThinkPad.

# 0.5.0 — Session & Authentication (TEST)

Incremental overlay over 0.4.0, whose appearance was confirmed by the user. Extract in ~/.config/swirldesk, run bash matrix-support/enable-session.sh, reselect MATRIX. The two optional shared dispatchers (power-menu.sh and bin/swirlfetch) are guarded by exact baseline comparisons and backed up; if customized, installer refuses both. Waybar's power and middle-click report directly open the MATRIX tools regardless of dispatcher installation. Super+Ctrl+P and Control Center POWER use the existing shared dispatcher. No new keybindings. Other themes and non-Hyprland sessions retain original dispatchers.

GTK3 power menu with Fuzzel fallback; destructive commands and suspend require explicit confirmation (Cancel default). Lock invokes hyprlock; suspend requires a running user hypridle, requests loginctl lock-session and uses existing hypridle before-sleep hook, then systemctl suspend. This checks prerequisites, not proof of compositor lock completion. Reboot/poweroff use systemctl, logout uses hyprctl dispatch exit. No sudo, no bypass of polkit or inhibitors, no credential handling. Lock screen remains dark, with date, check/failure colors and native Hyprlock authentication. Display manager/greeter, PAM, fingerprint policy and common hypridle config deliberately untouched; this is a session theme, not a system login replacement.

Fastfetch uses local ASCII logo, green keys, local system modules, no local-IP module. swirlfetch changes only in active MATRIX Hyprland sessions; direct `fastfetch` retains its config. Middle-click MATRIX // opens a held Kitty system-report window; falls back to original system-info menu when dependencies missing. No fonts or new packages installed. Existing wallpapers, profile switcher, icon theme, Control Center and Plasma remain unchanged. Third-party tray pixmap limits from 0.4 remain.

Rollback: switch to another theme first, run `bash matrix-support/rollback-session.sh` (checks shipped hashes, restores exact pre-session files plus guarded dispatchers). Run this before any 0.4 icon rollback. `disable-session.sh` alone restores shared dispatchers but leaves direct MATRIX Waybar links. Re-select desired theme after rollback.

Validation: session commands exercised only via mocks, including confirmation, cancellation, active-theme/session guard, suspend preconditions and original-dispatcher routing. Native GTK, real Hyprlock/PAM, actual power actions and Fastfetch rendering require local tests; no destructive real command was run.
