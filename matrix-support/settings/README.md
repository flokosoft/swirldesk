# MATRIX 0.9.1 TEST — Settings integration

Prerequisite: v0.9.0 installed and enabled. Extract from ~/.config/swirldesk, then `bash matrix-support/enable-settings.sh`. The existing Control Center entry `digital session` now opens the unified Settings Center. Direct: `/usr/bin/python3 ~/.config/swirldesk/themes/swirldesk-matrix/settings/settings.py menu`. Existing Fuzzel menu remains available via `session/digital/ctl.sh session-menu`. GTK3 is preferred; Fuzzel fallback if unavailable. No fonts bundled.

Presets set three existing preferences only: ECO = rain off, CRT off, saver off; BALANCED = rain on, CRT soft, saver off; IMMERSIVE = rain on, CRT classic, saver 180s. Wallpaper/profile, intro, sound, exit preferences are preserved. Rain can only run on code-rain and external power. CRT and automatic saver remain AC-only. No second power-management daemon. Preset labels are inferred from the three actual saved settings (otherwise custom). A preset doesn't change wallpaper; selecting CODE RAIN separately makes animated rain eligible. If an engine call fails, successful earlier edits are retained, and the UI reports the error and re-reads preferences. Changes are not a cross-engine transaction. CRT/rain visualization is visible on the real desktop after Apply; intro and saver have bounded preview commands. No new automatic shader recovery mechanism; existing guards and static wallpaper fallback remain in use. Preview on battery is a short explicit action, not an automatic idle effect.

`bash matrix-support/master-doctor.sh` runs existing Hyprland doctors and adds readback; textual MISMATCH/INFO lines remain relevant even if legacy doctors exit zero. Plasma is separate. CLI: settings.py status | menu | preset eco|balanced|immersive | set KEY VALUE | preview intro|saver. No power or authentication changes. On a failure, disable rain/CRT with existing ctl.sh commands if desired. Disable Settings before rolling back Digital Session: `bash matrix-support/disable-settings.sh` restores the exact original controller but retains saved preferences and new inactive files. Local customized controller is rejected by the integration installer. Neither common scripts nor FIELD, Plasma, GTK global configuration, Hypridle, Hyprlock, login manager, or workspaces are modified.

Tested: eight new unit test methods; nine existing session, six CRT, five rain; guarded apply/reapply/restore and customized baseline rejection; shell/Python syntax; archive. GTK/Wayland display not available in build environment, so GTK layout, real compositor and master doctor on installed user desktop are not live verified.
