# MATRIX 0.8.0 TEST — Digital Rain

Baseline: SwirlDesk original archive + MATRIX overlays through 0.7.1, confirmed working by user. This is an incremental Hyprland-only overlay. No fonts, media, root modifications, new system services, third-party network access or changes to shared scripts, Plasma, Waybar config, the other themes or the 0.7.1 digital manager. Existing static wallpapers and menu entries remain.

## Install

Extract into ~/.config/swirldesk, then `bash matrix-support/enable-rain.sh`. The installer replaces only the exact known profile.sh (or accepts the already-installed new copy); custom files are refused. Original and new profile are shipped with the package. Dependencies, if missing, install from Debian via `sudo apt install python3-gi python3-gi-cairo gir1.2-gtk-3.0 gir1.2-gtklayershell-0.1`. No packages installed automatically. GTK3 layer shell 0.9 is packaged in Debian 13. `bash matrix-support/rain-doctor.sh` reports integration, dependencies, preference, renderer state and local log. An absent dependency is optional and does not invalidate the static theme. `--check` imports libraries only; it is not a compositor test.

Select CODE RAIN LIVE // ANIMATION (AC ONLY) from the current visual profile selector in Waybar or Control Center. This applies the existing static code-rain image and sets state/matrix_rain_enabled=on. The normal CODE RAIN entry sets off; CLEAN and CONSTRUCT suppress rendering but retain the preference, so a programmatic return to code-rain or choosing LIVE can resume it. CLI: `themes/swirldesk-matrix/visual/rain/ctl.sh on|off|status|doctor`. To remove the integration, `bash matrix-support/disable-rain.sh`; this sets off and restores the exact original profile script, leaving assets inert. No theme restart required. Never overwrite customized profile scripts manually.

## Behavior and decisions

A GTK3 layer-shell bottom surface is created per GDK monitor, full anchored, exclusive zone -1, keyboard mode NONE and empty GDK input shape. The original swaybg remains behind it, without stopping any other background process. Dark backdrop, independent falling columns, variable trail length/speed, cached Pango glyph surfaces with locally installed JetBrainsMono Nerd Font (system fallback for missing glyphs). 12 FPS target (not a benchmark); no bundled font. Renderer only launches in a Hyprland/Wayland environment and after opt-in with active MATRIX, code-rain and matching static wallpaper cache. A per-compositor runtime lock prevents duplicates, with a 20s retry interval after unexpected failure. Existing Waybar status polling and successful profile application request launch; the --status call therefore can trigger an opt-in launch. On battery or unknown power the renderer destroys all surfaces and removes animation timer, but remains in a lightweight 1-second power/eligibility polling loop; resumes only when an external sysfs power supply is positively online. On leaving the theme, profile, changing wallpaper cache or disabling, it exits on the next poll; no killall. Waybar status polling will resume on login/reentry if opted in and the original wallpaper cache matches. Docking is handled by periodic monitor enumeration. This is not a power-meter or lock-screen detector, nor does it explicitly pause beneath maximized windows or on screen lock. Linux power-supply classification may differ by device; fail closed. Runtime logs under $XDG_RUNTIME_DIR/swirldesk-matrix-rain-<session hash>.

## Validation / live test

Five local unit test methods (power policy, eligibility, deterministic simulation bounds, guarded upgrade/restore/custom refusal, menu selections) passed, plus four existing visual regression tests on reconstructed baseline, and a real flock inheritance probe. Bash syntax, Python AST and archive integrity checked. Native GTK3/layer-shell dependencies are absent in the build environment; actual Wayland rendering, input transparency, output hotplug, charger removal/reconnection, login, and CPU/GPU usage NOT live verified. Test on AC: choose LIVE, confirm windows and panel input normal, unplug, verify static wallpaper within approximately one second, reconnect, verify rain returns. Select FIELD/Debian and confirm no renderer, then reselect MATRIX and choose static CODE RAIN and verify no renderer. If anything is wrong, run ctl.sh off and wait for next poll, then send rain-doctor output. If a renderer hangs, exit the Hyprland session to clean it up. No changes to authentication. Existing colorful Waybar tray limitations remain. Next: optional CRT mode or performance tuning after live validation.
